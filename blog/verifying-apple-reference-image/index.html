Verifying Apple Reference Image

Published on  31.10.2026

—

Repo

Executive summary With the new iPhone 18 Pro series, Apple created a new standard to verify the authenticity of images taken on iPhones, called Apple Reference Image. This system uses trusted hardware inside the iPhone’s camera sensor, in combination with Apple’s broader Private Compute Cloud ecosystem, in order to cryptographically certify an image as an authentic photograph. While already deployed in iOS 27 and announced on Apple’s Security Research blog [1], Apple did not provide any way to verify these images outside the iOS Photos App. Today we're presenting the first publicly available tool to inspect and verify images signed using Apple Reference Image, in addition to a deep dive into the technical details of the protocol.

Intro/Motivation Bit (internal structure title only) AI-generated images and videos are becoming increasingly indistinguishable from genuine photographs and recordings. As a result, the visual realism of an image is no longer a reliable indicator that it depicts something that actually happened. The consequences are already visible in everyday life: manipulated images spreading misinformation on social media, AI-enhanced apartment listings in New York misleading prospective tenants about the condition of properties, and AI-edited product photos potentially concealing defects in second-hand clothing sold on platforms such as Vinted [5]. The problem extends beyond online marketplaces. Experts from OpenAI and Meta recently warned the US judiciary that increasingly sophisticated deepfakes could make it extremely difficult to distinguish authentic audio and video evidence from fabricated material in court [2]. With traditional methods of detecting manipulation becoming less dependable, we need a way to establish the authenticity of an image rather than merely assess whether it looks real.

Explanation of general approach and C2PA vs Apple (internal structure title only) One approach to this problem is to establish a cryptographic link between an image and the camera that captured it. The C2PA standard already provides a way to attach signed provenance information to images, including a record of subsequent edits. Apple, however, argues that existing implementations do not go far enough: when an image is signed only after the camera's software processing, a compromised device could already have altered its contents. Apple Reference Image therefore signs pixel data inside the camera sensor, then uses Apple's Private Cloud Compute infrastructure to turn that signed capture into a verifiable photograph. This is an interesting security design, but it is not clear that it required a separate, Apple-specific format: C2PA does not itself mandate where signing happens, and can also accommodate hardware-backed capture. For now, Apple Reference Image is unavailable in the EU, without a specific public explanation.

How to verify (interactive bit starts here) - This needs a real Heading on the page

Below, we will walk through the Apple Reference Image protocol and how to verify it, using an interactive example. If you have an image from an iPhone 18 Pro series phone, you can upload it (technically, everything is processed locally in the browser) and use it for this explainer, otherwise we provide an example image.
